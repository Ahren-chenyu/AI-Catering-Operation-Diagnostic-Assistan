# AI餐饮经营助手

> 让餐饮经营者不仅知道门店发生了什么，还能知道该运营哪些用户、用什么策略增长，以及活动做得怎么样。

传统餐饮 SaaS 擅长记录和展示数据。本项目在数据之上叠加 **经营决策 + 用户增长** 两层能力，形成可演示的完整闭环：

```text
经营数据 → 经营诊断 → 用户分析 → RFM分层 → AI增长机会 → 营销策略 → 执行模拟 → 效果复盘
```

---

## 项目背景

中小餐饮门店每天都有营业额、客流、客单价、新老客数据，也越来越多地通过美团、抖音等公域获客。真正困难的往往不是「有没有数据」，而是：

> **知道数字变了，却不知道为什么变；更不知道该先运营谁、用什么权益、触达后效果如何。**

本产品把「看报表」升级为「经营诊断 + 增长运营」作品集级 MVP，适合向面试官展示：懂餐饮业务、懂用户增长、能设计 AI 应用场景、能把方案做成可运行产品。

---

## 用户痛点

| 痛点 | 表现 |
|------|------|
| 看不懂异常 | 营业额掉了，不知道主因是订单、客单还是新老客结构 |
| 找不到人 | 不清楚高价值、新客、沉睡、流失风险各自有多少、怎么运营 |
| 不会定策略 | 只会发通用优惠券，缺乏「目标人群 → 权益 → 渠道 → 时机」的结构化方案 |
| 复盘缺失 | 活动做完后缺少触达/核销/GMV/ROI 与下一轮建议 |

---

## 产品方案

双主线并行，互不破坏：

1. **经营诊断线（已有）**  
   异常发现 → 规则拆解 + 证据 → AI 解读 → 行动计划 → 到期复盘

2. **用户增长线（本次升级）**  
   增长 KPI → RFM 分层 → 机会识别 → 营销策略 → 任务模拟 → ROI 复盘

统一约束：

- 全站增长页共用 **一套确定性 Mock 数据集**（`asOfDate = 2026-08-26`，约 1800 用户）
- ROI 公式统一：`(活动收入 - 营销成本) / 营销成本`，并在 UI 明示
- 预测结果标注：**「MVP模拟预测，仅用于策略验证。」**

## 产品流程

```text
经营问题（驾驶舱 / 诊断）
        ↓

        ↓

        ↓
效果复盘（触达·核销·GMV·ROI·下一轮建议）
```

## AI 架构

```text
经营数据 + 用户数据 + 活动数据
        ↓
数据分析层（KPI / 趋势）
        ↓
规则引擎（异常 & 增长机会）
        ↓
用户标签 / RFM
        ↓
增长机会识别
        ↓
LLM（可选：DeepSeek 增强文案）
        ↓
AI 增长策略 → 营销任务 → 效果数据 → AI 复盘
```

### 四个 Agent（产品概念）

| Agent | 回答的问题 |
|-------|------------|
| 经营诊断 Agent | 生意发生了什么？ |
| 用户洞察 Agent | 哪些用户发生了变化？ |
| 增长策略 Agent | 应该对哪些用户采取什么策略？ |
| 效果复盘 Agent | 执行后效果如何？下一步怎么优化？ |

底层不强行 Multi-Agent 编排：以规则引擎为主，可选 LLM，失败自动回退，保证 Demo 可演示。

## 用户增长模型

核心指标（均由统一数据集计算）：

- 总用户数 / 本月新增（MoM）
- 月活跃用户（MAU）
- 30 日留存率
- 复购率（≥2 次消费占比）
- ARPU（近 30 天收入 ÷ MAU）
- 高价值用户数 / 流失风险用户数

趋势：30 日新增与活跃；近 6 个月复购率与 ARPU。

---

## RFM 模型

| 分层 | 含义 | 典型策略 |
|------|------|----------|
| 高价值 | 近、频、高额 | VIP / 专属新品 |
| 潜力 | 频次尚可、客单有空间 | 加价购 / 套餐升级 |
| 新用户 | 首购近、次数少 | 首购→复购 |
| 沉睡 | 长期未消费 | 唤醒召回 |
| 流失风险 | 曾活跃/高价值但频次下降 | 定向挽留 |

点击分层可查看用户明细与 **AI 用户画像**（仅引用用户字段，不编造冲突描述）。

---

## AI 增长机会

规则示例（与页面 KPI 同源）：

- 新客复购偏低 → 首购 7–14 天未复购人群
- 高价值活跃下降 → 频次下降 >30%
- 午餐增长机会 → 午餐订单连续走弱
- 客单价提升 → ARPU 下行且活跃稳定
- 增长质量风险 → 拉新加速但留存走弱

每条机会包含：发现 → 判断 → 目标人群 → 增长目标 → CTA。

## AI 营销策略

点击「生成增长方案」进入结构化策略页：

- 营销目标 / 目标人群与特征
- 推荐权益及原因
- 渠道与发送时间及原因
- **为什么推荐？**（数据 → 判断 → 策略）
- 短信 / 微信 / Push 文案
- 预计触达、领取、核销、GMV、成本、ROI（模拟预测）

## 本地运行方式

```bash
npm install
npm run dev
```

浏览器打开 [http://localhost:3000](http://localhost:3000)（默认跳转 `/dashboard`）。

生产构建：

```bash
npm run build
npm start
```

可选环境变量（经营诊断 LLM / 数据源，增长模块不依赖也能完整演示）：

- `DEEPSEEK_API_KEY`
- Supabase 相关变量（见既有 `.env.example` 如有）

CloudBase 部署（沿用现有脚本）：

```bash
npm run deploy:cloudbase
# 或带环境变量：
npm run deploy:cloudbase:env
```

## 面试演示路径（约 4 分钟）

1. `/dashboard`：经营异常 → 进入诊断（30s）  
2. `/growth`：增长 KPI 与复购/ARPU 异常（40s）  
3. `/growth/segments` → 某一分层：定位人 + AI 画像（40s）  
4. `/growth/opportunities` → 点「生成增长方案」（50s）  
5. `/growth/strategy/...`：讲清「为什么推荐」→ 创建营销任务（40s）  
6. `/growth/campaigns`：CMP-001 ROI 与下一轮建议（40s）  

一句话收束：**经营问题 → 用户问题 → AI 策略 → 执行 → 用 ROI 验证。**
